T2I (Text-to-Image): Generates a completely new image from scratch using only a text description.

I2I (Image-to-Image): Takes an existing image, adds noise to it, and uses a text prompt to reshape the overall composition into a new image. It treats the original image as a loose structural layout.

EDIT (Instruction Editing): Takes an existing image and applies a command or action (e.g., "make it rain", "add sunglasses", or "turn the cat into a dog"). It leaves the rest of the image entirely untouched while precisely altering only the subject of your instruction.
The Bottom "REF" Layer: Your diagram also shows REF branching down from EDIT. This represents Reference-guided Editing. If you choose the EDIT path, you can optionally provide a second reference image. For example, you can give the AI a photo of yourself (Input Image), an instruction like "Make me wear this jacket" (Text Prompt), and a picture of a jacket from an online store (Reference Image). The EDIT engine will seamlessly graft the reference object onto the original target.

VANILLA UPSTREAM STABLE-DIFFUSION.CPP MODEL CATALOG
===================================================

This catalog contains image-generation and image-editing models
compatible with the upstream stable-diffusion.cpp project.

This portable project is intended to support FOUR distinct
image workflows:

    TEXT-TO-IMAGE
    IMAGE-EDITING
    IMAGE-TO-IMAGE
    REFERENCE / CONDITIONING

These workflows are related but are NOT interchangeable.

stable-diffusion.cpp supports multiple generations of diffusion
and diffusion-transformer models. These model families do NOT
all use the same files or command-line options.

Supported weight formats include:

- GGUF
- Safetensors
- PyTorch checkpoint (.ckpt, .pth, .pt)

Supported GPU backend for this portable project:

- Vulkan


============================================================
THE FOUR REQUIRED IMAGE WORKFLOWS
============================================================


1. TEXT-TO-IMAGE
----------------

Capability tag:

    T2I

Purpose:

Generate a completely new image from a text prompt.

Input:

    text prompt

Output:

    new image


Example:

    "A cinematic photograph of a red fox walking through
     a snowy forest at sunrise."

        |
        v

    NEW IMAGE


This is the traditional image-generation workflow.


============================================================


2. IMAGE-EDITING
----------------

Capability tag:

    EDIT

Purpose:

Modify an existing image according to a natural-language
instruction.

Input:

    existing image
    text instruction

Output:

    modified image


Example:

    Existing image
        +
    "Change the jacket from black to red."

        |
        v

    EDITED IMAGE


Dedicated image-editing models should be cataloged separately
from ordinary text-to-image models.

Current stable-diffusion.cpp supports dedicated image-editing
families including:

- FLUX.1-Kontext-dev
- Qwen Image Edit
- LongCat Image Edit
- Boogu Image Edit
- Mage-Flow-Edit


============================================================


3. IMAGE-TO-IMAGE
----------------

Capability tag:

    I2I

Purpose:

Use an existing image as the starting point for generating
a new image.

Input:

    existing image
    text prompt
    transformation strength / related parameters

Output:

    NEW generated image

The output is derived from the source image but is a newly
generated image.

Example:

    Existing photograph
        +
    "Turn this into an oil painting."
        +
    transformation strength

        |
        v

    NEW IMAGE


I2I is NOT the same as dedicated instruction-based image
editing.

The model may preserve some structure from the source while
allowing substantial changes.


============================================================


4. REFERENCE / CONDITIONING
---------------------------

Capability tag:

    REF

Purpose:

Use one or more reference images to influence a NEW generated
image.

The reference image is used as conditioning information.

Input:

    reference image
    text prompt

Output:

    NEW generated image


Example:

    Reference photograph of a person
        +
    "A cinematic portrait of this person
     standing in a futuristic city at night."

        |
        v

    NEW IMAGE


The reference image is NOT simply edited.

The purpose is to use characteristics of the reference image
to influence generation.


============================================================
REFERENCE / CONDITIONING IS NOT ONE SINGLE TECHNIQUE
============================================================

Reference conditioning can be implemented through different
mechanisms depending on the model family.

Examples include:

- IP-Adapter
- image encoders
- vision-language models
- ControlNet
- model-specific reference-image conditioning
- multimodal diffusion transformers

Therefore the catalog must identify the actual mechanism used
by each model.

Do NOT assume that all reference-image workflows use
IP-Adapter.


============================================================
IMPORTANT DISTINCTION
============================================================

These four workflows should remain separate:

    T2I
        Text -> NEW IMAGE

    EDIT
        IMAGE + INSTRUCTION -> MODIFIED IMAGE

    I2I
        IMAGE + PROMPT + STRENGTH -> NEW IMAGE

    REF
        REFERENCE IMAGE + PROMPT -> NEW IMAGE


An individual model may support one, several, or all of these
capabilities.


============================================================
MODEL CAPABILITY TAGS
============================================================

Every model entry must contain one or more capability tags.

Valid tags:

    T2I
        TEXT-TO-IMAGE

    EDIT
        IMAGE-EDITING

    I2I
        IMAGE-TO-IMAGE

    REF
        REFERENCE / CONDITIONING


Examples:

    CAPABILITY:
        T2I

    CAPABILITY:
        T2I, I2I

    CAPABILITY:
        EDIT, REF

    CAPABILITY:
        T2I, EDIT, REF


Do NOT infer capability solely from the model family name.

============================================================
IMAGE EDITING MECHANISMS
============================================================

IMAGE EDITING can mean several different things.


1. INPAINTING
-------------

Existing image
    +
mask
    +
prompt
    |
    v
modified region


2. IMAGE-TO-IMAGE
-----------------

Existing image
    +
prompt
    +
transformation strength
    |
    v
new generated image


3. INSTRUCTION-BASED EDITING
----------------------------

Existing image
    +
natural-language instruction
    |
    v
modified image


4. REFERENCE-CONDITIONED GENERATION
------------------------------------

Reference image
    +
text prompt
    |
    v
new generated image


These are different workflows.

The catalog must not collapse them into a generic
"image-to-image" category.


============================================================
REFERENCE / CONDITIONING MECHANISMS
============================================================

The following mechanisms may provide reference conditioning:

    IP-Adapter

    ControlNet

    Vision encoder

    Vision-language model

    Model-specific reference conditioning

    Multimodal diffusion transformer


The required files and command-line parameters vary.

For example:

SD1.5 / SDXL:

    IP-Adapter

may provide reference-image conditioning.

Mage-Flow-Edit:

    Qwen3-VL
    vision component
    reference image

provides multimodal image conditioning.

These are architecturally different approaches.


============================================================
MODEL COMPONENT TERMINOLOGY
============================================================


DIFFUSION MODEL

The primary image-generation neural network.

Typical option:

    --diffusion-model


VAE

Variational Autoencoder.

Converts between latent representations and image pixels.

Typical option:

    --vae


LLM / TEXT ENCODER

A language model used by some modern diffusion families to
encode text prompts.

Typical option:

    --llm


CLIP-L

A CLIP text encoder used by some model families such as FLUX.1.

Typical option:

    --clip_l


T5-XXL

A large text encoder used by FLUX.1.

Typical option:

    --t5xxl


VISION ENCODER

Processes an image so that image information can be used as
conditioning.

The exact model and option depend on the model family.


VISION-LANGUAGE MODEL

A multimodal language model capable of processing both text
and images.

For example, Mage-Flow uses Qwen3-VL for text and image
conditioning.


LLM VISION COMPONENT

Some multimodal models require an additional vision component.

For example, the current Mage-Flow-Edit documentation uses:

    --llm_vision

with a Qwen3-VL vision component.

This is NOT the same thing as an ordinary text encoder.


IP-ADAPTER

An image-conditioning mechanism supported by stable-diffusion.cpp
for supported model families including SD1.5 and SDXL.

It can use reference images to influence generation.

It is NOT a replacement for the base diffusion model.


CONTROLNET

An additional conditioning model supported for SD1.5.

It can guide generation using structural information such as
edges, depth, poses, or related controls.

It is NOT required for ordinary T2I generation.


LORA

A small adapter that modifies the behavior or style of a base
model.

LoRA is NOT a replacement for the base diffusion model.

============================================================
CATALOG RULE
============================================================

The model downloader must NOT simply download the first
.gguf or .safetensors file it finds.

A model definition is a COMPLETE COMPONENT SET.

For example:

    Z-IMAGE-TURBO

is not simply:

    z_image_turbo.gguf

It is:

    diffusion model
    +
    VAE
    +
    Qwen3 text model


Likewise:

    FLUX.1

is not simply:

    flux.gguf

It requires the appropriate:

    diffusion model
    +
    VAE
    +
    CLIP-L
    +
    T5-XXL


And a multimodal editing model such as Mage-Flow-Edit may
require:

    diffusion model
    +
    VAE
    +
    Qwen3-VL
    +
    vision component
    +
    reference image


Therefore the downloader must understand the MODEL FAMILY
and MODEL CAPABILITY before downloading anything.
